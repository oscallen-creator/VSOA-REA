# Media tools inventory (VIDEO `VID`, AUDIO `AUD`, shared `MED`)

## Overview
Tangerine's video and audio tools are "file tools": the user drops one or more files onto a tool slice of the tools wheel, a
`FileToolOptionsWindowController` panel opens with the tool's editor (timeline / waveform / form), and a primary "Save ..." button
writes a NEW file beside the original (original untouched; output folder needs sandbox folder access). Every media
tool in Tangerine is implemented by shelling out to the bundled `Tools/ffmpeg` (progress parsed from `-progress pipe:1`; recipes below
are behavior hints, not to be copied). FileChanger cannot use ffmpeg, so almost everything is routed to AVFoundation.
Model keys seen (S:22200-22260): trimStartSeconds, trimDurationSeconds, cropX/Y/Width/Height, cropSelections, playbackSpeed, snapshotTimes,
splitTimes, splitRemovedClips, splitExportMode (clips|merged), audioVisualization (waveform|staticImage), staticImageURL, videoCanvas
(automatic|square|landscape|portrait), autoTrimSilence, silenceThresholdDB, audioChannelCount, audioLeftVolume, audioRightVolume,
normalizationTargetLoudness/LoudnessRange/TruePeak, redactions, redactionStyle (solid|blur), bleepRanges, compressionTargetMode
(preset|fileSize|percentage), targetVideoEncoding, targetSizeText/Unit, compressionReductionPercentage, videoCompression (balanced|strong).
Gating: Tangerine counts "free uses" and shows an Unlock paywall for all tools (conversions + tools); FileChanger is fully unlocked, ignore.
Route legend: `AVF` = AVFoundation (AVAssetExportSession / AVMutableComposition / AVAssetReader+Writer), `AVE` = AVAudioEngine/AVAudioFile,
`CI` = CoreImage, `SW` = SwiftUI/AppKit UI only, `needs:ffmpeg` = no clean native path.
Evidence: `S:<line>` strings.txt, `L:<addr>` smallstrings.tsv (hex tail), `C` camel.txt type name only. Addresses are tails like `L:1fe0d8`.

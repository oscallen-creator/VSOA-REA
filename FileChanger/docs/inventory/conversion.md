# Tangerine 2.0.4 - Conversion engine, formats, document and PDF tools

Evidence keys: `S:<line>` strings.txt, `L:<addr>` smallstrings.tsv, `D:<file offset>` static data tables decoded straight from the Mach-O (cleaner than strings: these are real Swift `[ConversionFormat]` arrays and the per-format switch table), `R:<file>` bundle resource names, `M:` macOS 15 probe run on this Mac (ImageIO type lists, `/System/Library/Filters`).
Route values: `native:<framework>`, `needs:<tool>`, `custom` (must be hand-written Swift), `n/a`.
Paywall note: Tangerine gates conversions and tools behind "Unlock" (free-use counter, "Convert multiple files at once" is paid). FileChanger is fully unlocked; nothing else is recorded here.

## 1. Overview

- Conversion is drag-driven: files dropped on the Conversion wheel pick an output `ConversionFormat`; result is written next to the original (S:28650 "The new copy is saved next to the original."). The sandbox folder-access prompt (S:28242) is the only reason output ever goes elsewhere.
- `ConversionFormat` has **47 cases** (raw values, decoded from reflection strings and from an in-order `allCases` array, D:0xa5f400): `jpg png webp heic tiff svg avif bmp raw pdf mp3 m4a wav flac ogg opus aiff wma mp4 mov mkv webm avi wmv gif docx pages ppt pptx txt md rtf rtfd textClipping html epub xlsx xls ods csv tsv srt vtt zip tar gzip rar`. The `gzip` case has raw value `gz`.
- Which outputs a source offers is one switch (`targets(for:)`, code at 0x1002940c8, jump table D:0x839000) returning one of 14 static arrays, then **removing the source itself and the 7 input-only formats** (`raw rar ppt xls rtf rtfd textClipping`, D:0xa5f708). That fully determines the matrix (section 2); all cells there are `observed` (decoded), only the engine behind each cell is inferred.
- Engines: ImageIO/CoreImage for images; bundled ffmpeg (static, arm64, VideoToolbox/AudioToolbox, libmp3lame, libopus, libvpx, libdav1d, libwebp, **no** libx264/libaom) and cwebp for media and WebP; hand-written Swift document model ("structured" reader/writer set) for docx/pages/rtf/rtfd/md/txt/html/epub; bundled JRE + Apache POI/PDFBox helper jar for xlsx/xls/ods/csv/tsv/ppt/pptx; WKWebView offscreen renderers (docx-preview in `OfficePreview.js`, EPUB, SVG/vector); `PagesWriter.js` run in JavaScriptCore to read/write `.pages` from `PagesTemplate.pages`; PDFKit/Quartz for the PDF tools; `/usr/bin/{tar,gzip,zip,ditto}` for archives.
- Hard limits seen: 128 MB document/render/import limit (Pages, DOCX, RTFD, spreadsheet, PowerPoint, structured export), 32 MB text import limit, 5-minute cap on the Java converters, PDF/A page edge 3 to 14,400 pt, Word page edge 22 in, EPUB archive expansion/safety limits.
- Progress for ffmpeg jobs comes from `-progress pipe:1 -nostats` key=value lines; total duration is parsed from ffmpeg's own banner (no ffprobe bundled).
